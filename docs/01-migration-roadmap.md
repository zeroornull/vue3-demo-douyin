# 迁移总路线图

## 1. 为什么必须分轮

旧项目同时存在包管理器、框架主版本、类型严格度、构建配置、非标准宏、全局副作用和大规模页面迁移问题。若一次性修改，失败时无法判断是 Bun、依赖兼容、类型错误、路由变化还是业务回归。

本路线把迁移拆成六轮。每轮都遵循同一循环：

```text
定义行为与成功标准
        ↓
做最小可审查改动
        ↓
运行本轮最小证明
        ↓
记录差异与剩余风险
        ↓
通过门禁后进入下一轮
```

## 2. 轮次总览

### 第 0 轮：建立行为基线

**目的**：证明“旧项目现在是什么样”，而不是凭记忆迁移。
**主要产物**：路由清单、关键流程、截图、网络/Mock 契约、资源清单、旧构建结果。
**禁止事项**：不升级依赖、不格式化旧代码、不修复无关问题。
**门禁**：任何人按文档都能重复运行旧项目并得到相同的核心证据。

### 第 1 轮：建立 Bun + 官方 Vue TypeScript 骨架

**目的**：得到不含业务代码的可运行、可检查、可测试、可构建基座。
**主要产物**：`package.json`、`bun.lock`、Vue/Vite/TS 配置、ESLint flat config、Vitest、Playwright、CI。
**禁止事项**：不复制 128 个页面，不导入旧全局 mixin，不复刻 CDN 配置。
**门禁**：冻结安装、类型检查、lint、单测、E2E 冒烟和 build 全绿。

### 第 2 轮：建立严格 TypeScript 迁移通道

**目的**：定义类型边界和 JS→TS 的机械步骤，让后续页面迁移不会重新累积 `any`。
**主要产物**：领域模型、API 结果类型、路由 meta 扩展、Store 类型、事件类型、环境声明、迁移计数器。
**禁止事项**：不靠关闭 `strict`、打开全局 `allowJs` 或批量 `@ts-ignore` 通关。
**门禁**：新骨架严格模式全绿；首个代表性纵切没有隐式 `any` 和非标准宏。

### 第 3 轮：迁移核心基础设施

**目的**：先建立所有页面依赖的稳定平台。
**主要产物**：Router、Pinia、请求层、Mock/fixture、事件、点击/滑动能力、图片懒加载、构建版本和环境配置。
**禁止事项**：页面不得直接绕过请求层；不得重新引入全局 DOM 原型修改。
**门禁**：应用壳启动、导航、Store 初始化、Mock/API 请求、错误处理和构建均通过测试。

### 第 4 轮：按业务纵切迁移页面与资源

**目的**：以用户可感知流程为单位迁移，而不是按文件夹机械搬运。
**主要产物**：页面、组件、页面所需 Store/API、资源和对应测试。
**禁止事项**：不一次性复制全部 `public/`；不提交无法被路由或测试访问的半成品。
**门禁**：纵切的行为、视觉、路由、数据和性能预算均达标。

### 第 5 轮：质量收口、部署和最终切换

**目的**：证明新应用可发布，并移除临时兼容与废弃依赖。
**主要产物**：完整 CI、生产构建、部署配置、监控/回滚说明、依赖审计和最终迁移矩阵。
**禁止事项**：不能因“本地能跑”跳过冻结安装和生产预览。
**门禁**：关键 E2E、性能预算、部署冒烟、回滚演练全部通过，且新代码不引用 `legacy/`。

## 3. 推荐时间盒

时间盒取决于参与人数，下表表达的是相对比例，不是承诺日期：

| 轮次 | 建议占比 | 原因 |
| --- | ---: | --- |
| 第 0 轮 | 10% | 基线越弱，后面返工越多 |
| 第 1 轮 | 10% | 骨架小，但版本/工具兼容必须严谨 |
| 第 2 轮 | 15% | 类型模型决定后续迁移效率 |
| 第 3 轮 | 20% | 核心基础设施影响所有页面 |
| 第 4 轮 | 35% | 页面、交互和资源是最大工作量 |
| 第 5 轮 | 10% | 发布证明和清理不可省略 |

## 4. 每轮统一验收记录

在每一轮的 PR 或迁移记录中填写：

```markdown
## 目标
- 本轮只改变：
- 明确不改变：

## 输入基线
- legacy 来源文件：
- 基线截图/测试：
- 依赖/运行时版本：

## 变更
- 新增：
- 删除：
- 替换：

## 验证证据
- bun install --frozen-lockfile：
- bun run type-check：
- bun run lint：
- bun run test:unit --run：
- bun run test:e2e：
- bun run build：
- 视觉/性能证据：

## 差异与风险
- 有意差异：
- 未解决风险：
- 回滚点：
```

## 5. 全局停止条件

出现以下任一情况，应停止扩展范围，先修复当前轮：

- 锁文件在相同输入下不稳定或 CI 与本地解析出不同主版本。
- 只能通过关闭严格模式、跳过 lint/测试或忽略错误才能构建。
- 生产运行时仍从 CDN 获得另一份 Vue/Router。
- 新页面需要直接读取 `legacy/` 才能工作。
- 路由、Store 或 Mock 的兼容层持续扩张且没有删除计划。
- 无法说明一项新依赖的用途、维护状态和删除条件。
- 基线行为不存在证据，争议只能靠主观记忆解决。

## 6. 依赖关系

```text
第 0 轮（证据）
   ↓
第 1 轮（工具链）
   ↓
第 2 轮（类型规则）
   ↓
第 3 轮（平台能力）
   ↓
第 4 轮（业务纵切，可分批）
   ↓
第 5 轮（发布与删除）
```

第 4 轮内部可以并行迁移互不依赖的纵切，但 Router、Store 公共类型、设计 token 和请求层属于共享文件，应先指定所有者，避免相互覆盖。
